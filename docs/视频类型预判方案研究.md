# 视频类型预判方案研究：停顿比 vs 评分分布信号

> 研究日期：2026-07-09
> 数据基础：8 条人工标注电商短视频（4 口播 + 4 评测），含完整 ASR 输出、5 维密度评分、MMR 帧选择结果
> 问题：`classify_video_type()` 使用停顿比（>1.5s 间隔 / 总时长 < 0.15 → 口播）做视频类型预判，工程中不可靠，需要找到替代方案

---

## 1. 问题背景

Token-Saver 算法的核心假设是**信息在视频时间轴上非均匀分布**。在评测类视频中，产品特写、价格数字、对比展示集中在少数秒内，评分曲线有明显峰值，Token-Saver 可以有效捕获这些关键帧。但在口播类视频中，50%+ 的秒都是"关键帧"（人脸固定、信息均匀分布），任何内容自适应方法都无法击败均匀采样。

因此需要在管道中判断视频类型，决定走 Token-Saver 密度选择还是回退均匀采样。现有方案使用 ASR 词级时间戳计算停顿比，但工程中表现不可靠。

---

## 2. 候选信号全集

从 8 条视频的 pipeline 输出中提取了 16 个候选信号，分为三类：

### 2.1 纯 ASR 信号（不依赖视觉/评分）

| 信号 | 计算方式 | 直觉 |
|------|---------|------|
| `pause_ratio` | sum(gap > 1.5s) / total_duration | 口播连续说话，停顿少 |
| `speech_rate_mean` | 每秒平均词数 | 口播语速均匀 |
| `speech_rate_cv` | 每秒词数的变异系数 | 口播语速方差小 |

### 2.2 评分分布信号（需要跑完评分 pipeline，但评分是纯 CPU 的）

| 信号 | 计算方式 | 直觉 |
|------|---------|------|
| `score_mean` | composite_scores 均值 | — |
| `score_std` | composite_scores 标准差 | 评测分数方差大 |
| `score_cv` | std / mean（变异系数） | 评测信息分布更不均 |
| `score_spread` | (p90 - p10) / mean | 评测分数跨度更大 |
| `score_peak_ratio` | max / mean | 评测有更突出的峰值 |
| `score_entropy_norm` | 分值直方图熵（归一化） | 口播分值集中在窄区间 |
| `score_skew` | (mean - median) / std | 评测右偏（少数峰值拉高均值） |

### 2.3 视觉/耦合信号（需要解码视频）

| 信号 | 计算方式 | 直觉 |
|------|---------|------|
| `scene_density` | 场景边界数 / 总秒数 | 评测画面切换更频繁 |
| `coupling_ratio` | 耦合帧数 / 总秒数 | 口播文本-视觉耦合更高 |

## 3. 实证分析

### 3.1 停顿比：为什么不可靠

在 8 条有音轨视频上的实测：

|------|------|-------------|------|

| M-42198d98eb40 | 口播 | 0.112 | ✗ 误判为评测 |
| M-782f8ea8c442 | 口播 | 0.000 | ✓ 正确 |
| M-9a12ab3f34c9 | 口播 | 0.015 | ✓ 正确 |
| M-3d7804786354 | **评测** | **0.000** | **✗ 误判为口播** |
| M-3e9018bc52ea | **评测** | **0.000** | **✗ 误判为口播** |
| M-720f4960f5ed | **评测** | **0.000** | **✗ 误判为口播** |
| M-84e1d947b553 | 评测 | 0.278 | ✓ 正确 |

- **3/4 评测视频的停顿比也是 0.000**，与口播完全无法区分
- 分类准确率：62.5%（仅略优于随机）
- Cohen's d = 0.414（小效应量，< 0.5 的标准阈值）

### 3.2 停顿比失效的三个根本原因

**原因一：ASR 引擎的天然行为。** Qwen3 ASR Flash（以及所有端到端 ASR 模型）学习的是"语音 → 文本"映射，而非"语音 → 静音"映射。当说话人自然停顿（换气、思考）时，模型倾向于输出连续词序列而不插入静音标记。只有当音频 track 出现完整的 dropout（无任何人声或背景音）时，才会在 word timestamps 上产生 >1.5s 的 gap。这不是 Qwen3 的缺陷，而是 E2E ASR 的标准行为。

**原因二：电商视频的背景音乐。** 几乎所有电商短视频都有连续背景音乐（BGM）。即使主持人停顿 3-5 秒展示产品，背景音乐仍在持续播放。ASR 不会将这 3 秒标记为"无词窗口"，因为音频中根本没有静音 — 只有"没有人声的音乐"。word timestamps 上看不到 gap。

**原因三：停顿比与视频类型的因果关系不成立。** 评测视频不等于"有停顿"（M-3d7804786354 从第 1 秒讲到第 43 秒，中间几乎没有停顿），口播视频也不等于"无停顿"（M-42198d98eb40 有明显的产品展示沉默段）。电商视频中，"有无停顿"取决于主持人风格和剪辑节奏，而非视频类型。

**结论：停顿比在理论上（ASR 行为假设不成立）和实践上（电商视频声学特征）都存在根本性缺陷。不应作为分类依据。**

### 3.3 所有信号的分离能力比较

按 Cohen's d 降序排列（口播 vs 评测，n=8）：

| 排名 | 信号 | Cohen's d | 最佳准确率 | 需要视觉？ | 需要跑评分？ |
|------|------|-----------|-----------|-----------|-------------|
| 1 | scene_density | **1.313** | **87.5%** | 是 | 否 |
| 2 | speech_rate_mean | 1.110 | — | 否 | 否 |
| 3 | score_std | 1.023 | — | 否 | 是 |
| 4 | coupling_ratio | 0.845 | — | 是 | 是 |
| 5 | score_spread | 0.818 | 62.5% | 否 | 是 |
| 6 | score_entropy_norm | 0.627 | — | 否 | 是 |
| 7 | score_cv | 0.607 | 75.0% | 否 | 是 |
| 8 | speech_rate_cv | 0.515 | 62.5% | 否 | 否 |

关键发现：
- **纯 ASR 信号**（pause_ratio, speech_rate_cv）的天花板是 62.5% 准确率

- **评分分布信号**（score_cv, score_std）处于中间地带：评分本身是纯 CPU 的快速操作（jieba 分词 + 5 维统计量），代价远低于视频解码

## 4. 推荐方案：Score-then-Decide

### 4.1 核心思路

**不做二进制预分类。跑完评分后，用评分分布的形状（peakiness）来决定采样策略。**

这个思路的理论基础是：

> Token-Saver 的核心假设是"信息在时间轴上非均匀分布"。
> `score_cv`（评分变异系数）直接度量了这个假设的成立程度。
> CV 低 → 假设不成立 → 回归均匀采样。
> 这不是一个 hack，而是对算法适用条件的自检。

### 4.2 算法流程

```
video.mp4
    │
    ├── [Stage 1] Qwen3 ASR Flash → word timestamps
    ├── [Stage 2] jieba 分词 + 5-dim 文本密度评分 → composite_scores[]
    │
    ├── peakiness = std(scores) / mean(scores)    # O(n), n ≈ 30-120
    │
    ├── if peakiness < 0.15:
    │       → 纯 Uniform 采样
    │       （分值分布过于平坦，TS 无优势）
    │
    ├── elif peakiness > 0.22:
    │       → 纯 Token-Saver Top-K 评分选择
    │       （有清晰信息峰值，TS 显著优于 Uniform）
    │
    └── else:   # 0.15 ≤ peakiness ≤ 0.22
            → 混合策略：60% 帧按评分选 + 40% 帧均匀填充
            （灰色地带，兼顾峰值捕获与覆盖均匀性）
```

### 4.3 为什么这个方案最优

**a) 零额外计算成本。** 5 维文本密度评分已经在 pipeline 中跑完了。`peakiness` 的计算是 numpy 的 O(n) 操作（n = 视频秒数，通常 30-120）。不需要额外的 API 调用、视频解码或模型推理。

**b) 理论一致性。** 不同于停顿比这种"外部启发式"，评分分布信号与 Token-Saver 的帧选择使用的是同一套信息源（5 维文本密度）。评分本身告诉你它自己是否有用 — 这是一种自检机制而非外部分类器。

**c) 自然降级。** 当评分接近均匀时（CV 低），Top-K 选择天然会选出近似均匀分布的帧。即使 peakiness 阈值设得不准，也不会产生灾难性失败 — 因为算法的输出是连续的，而非二进制的。

**d) 与实验结论一致。** 你的 Round 1 实验结论是"口播视频 TS ≈ Uniform，评测视频 TS > Uniform"。`score_cv` 的区分方向与此完全吻合：

| 视频 | 类型 | score_cv | 实验结论 |
|------|------|----------|---------|
| M-42198d98eb40 | 口播 | 0.088 | Uniform 应该更好（评分最平坦） |
| M-84e1d947b553 | 评测 | 0.142 | 灰色地带 |
| M-9a12ab3f34c9 | 口播 | 0.155 | 灰色地带 |
| M-3e9018bc52ea | 评测 | 0.168 | 灰色地带 |
| M-782f8ea8c442 | 口播 | 0.208 | 零耦合口播，Uniform 赢了 |
| M-14507b1e4eb0 | 口播 | 0.214 | 灰色地带 |
| M-3d7804786354 | 评测 | 0.221 | TS 应该更好 |
| M-720f4960f5ed | 评测 | 0.245 | TS 显著更好（最强峰值） |

### 4.4 阈值校准建议

当前阈值（0.15 / 0.22）基于 8 条视频的分布。建议在生产环境中：

1. 收集 50+ 条视频的 `(score_cv, 人工标注类别, TS vs Uniform 效果对比)` 三元组
2. 以"TS 是否显著优于 Uniform"为 ground truth 标签
3. 绘制 score_cv 的 ROC 曲线，选择最佳决策阈值
4. 对灰色地带的混合比例（当前 60/40）做参数扫描

### 4.5 代码实现

```python
import numpy as np

def select_frames_adaptive(
    composite_scores: list,
    budget: int,
    total_seconds: int,
    low_threshold: float = 0.15,
    high_threshold: float = 0.22,
    blend_ratio: float = 0.6,
) -> list:
    """
    Score-aware frame selection with automatic fallback to uniform.

    Args:
        composite_scores: Per-second importance scores (0-10 scale)
        budget: Number of frames to select
        total_seconds: Video duration in seconds
        low_threshold: Below this CV, use pure uniform
        high_threshold: Above this CV, use pure score-based selection
        blend_ratio: In gray zone, fraction of frames selected by score

    Returns:
        Sorted list of selected frame indices (0-indexed seconds)
    """
    scores = np.array(composite_scores, dtype=float)
    cv = float(np.std(scores) / (np.mean(scores) + 1e-10))

    if budget <= 0:
        return []

    if cv < low_threshold:
        # Scores too flat — uniform is equally good and cheaper
        return _uniform_sample(budget, total_seconds)
    elif cv > high_threshold:
        # Clear information peaks — score-based selection wins
        return _top_k_with_gap(scores, budget, total_seconds)
    else:
        # Gray zone: blend both strategies
        n_score = max(1, int(budget * blend_ratio))
        n_uniform = budget - n_score

        selected = set(_top_k_with_gap(scores, n_score, total_seconds))
        min_gap = max(1, total_seconds // (budget * 2))

        # Fill remaining slots with uniform candidates (respecting min gap)
        uniform_frames = _uniform_sample(budget * 2, total_seconds)
        for f in uniform_frames:
            if len(selected) >= budget:
                break
            if all(abs(f - s) >= min_gap for s in selected):
                selected.add(f)

        return sorted(selected)


def _uniform_sample(budget: int, total_seconds: int) -> list:
    if total_seconds <= 1:
        return [0] * min(budget, total_seconds)
    step = (total_seconds - 1) / max(budget - 1, 1)
    return sorted(set(
        min(int(step * i), total_seconds - 1) for i in range(budget)
    ))


def _top_k_with_gap(scores: np.ndarray, budget: int, total_seconds: int) -> list:
    if budget >= total_seconds:
        return list(range(total_seconds))

    # Ensure first and last are included
    scores = scores.copy()
    scores[0] = max(scores[0], scores.max() * 1.1)
    scores[-1] = max(scores[-1], scores.max() * 1.1)

    min_gap = max(1, total_seconds // (budget * 2))
    ranked = sorted(range(total_seconds), key=lambda t: scores[t], reverse=True)

    selected = set()
    for t in ranked:
        if len(selected) >= budget:
            break
        if all(abs(t - s) >= min_gap for s in selected):
            selected.add(t)

    return sorted(selected)
```

# 删除这个函数
def classify_video_type(words: List[dict], total_seconds: int) -> str:
    """停顿比 < 0.15 → 口播（回退 Uniform），否则 → 评测（走密度选择）"""
    if total_seconds <= 0:
        return "评测"
    pause_sec = 0.0
    prev_end = 0.0
    for w in words:
        gap = w["start"] - prev_end
        if gap > 1.5:

        prev_end = w["end"]
    return "口播" if (pause_sec / total_seconds) < 0.15 else "评测"

## 6. 局限性

1. **样本量有限（n=8）**。阈值 0.15/0.22 是基于 8 条视频的初步校准，生产环境需要更大样本重新校准。
2. **仅覆盖中文电商场景**。其他领域（新闻、Vlog、教育）的评分分布特征可能不同。
3. **score_cv 在灰色地带（0.15-0.22）的区分能力有限**。6/8 条视频落入此区间（包括 3 条口播和 3 条评测），混合策略的 60/40 比例是启发式设定的。
4. **未覆盖无音轨视频**。无音轨的剪辑大片（如 M-00fa7a854582）走 visual-only scoring 路径，score_cv=0.458，会被正确识别为"有信息峰值"。
5. **依赖评分质量**。如果 5 维评分本身的校准有偏差（权重需要 retrain），自适应策略的阈值也需要相应调整。

---

## 7. 结论

**不要用停顿比。** 它与其他任何候选信号相比都是最差的（Cohen's d=0.414，准确率 62.5%），并且在理论上（ASR 对静音的不可观测性）和实践上（电商视频的 BGM 特征）都存在根本性缺陷。

**用评分分布自检替代预分类。** `score_cv`（变异系数）直接度量了"信息是否非均匀分布"这一关键假设，不需要额外计算，自然降级，且与所有实验结论一致。这不是一个更好的分类器 — 这是一个更根本的方案：让评分自己告诉你它是否有用。
